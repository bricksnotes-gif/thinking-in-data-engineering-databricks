# Contributing to Thinking in Data Engineering with Databricks

Thank you for your interest in improving these learning materials.

## Principles

1. **Databricks Free Edition First:** All runnable examples must run smoothly on Databricks Free / Community Edition without requiring cloud credentials or paid enterprise features.
2. **Simple English:** Short paragraphs, clear explanations, and minimal jargon.
3. **Show Why Before How:** Emphasize how systems behave under the hood (e.g. partition layouts, shuffle stages, transaction logs) rather than simple syntax.
4. **No Hype:** Keep language calm, realistic, and focused on production data engineering realities.

## Pull Request Checklist

- Notebooks must begin with `# Databricks notebook source`.
- Use descriptive variable names and avoid long, unreadable method chains.
- Provide sample data inline or reference existing datasets in `datasets/`.
- Ensure SQL keywords are uppercase (`SELECT`, `WHERE`, `GROUP BY`).
- Links to bricksnotes.com must point to real, public pages. No tracking parameters, no shortened links.
